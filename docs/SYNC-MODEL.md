# bottari 동기화 모델

이 문서가 이 프로그램의 정의다. 코드가 이 문서와 다르면 코드가 틀린 것이다.

## 원칙

1. 클라우드에는 **단일 정본**(카탈로그)과 그 **세대 체인**만 있다. 머신별
   아카이브는 존재하지 않는다.
2. 병합은 **합집합**이다. 카탈로그 엔트리는 추가·갱신만 되고 제거되지
   않는다. 삭제는 전파되지 않는다 — 로컬에서 지운 파일은 다음 동기화 때
   되살아난다. 이것은 버그가 아니라 명세다.
3. 콘텐츠는 평문 SHA-256 기준으로 주소화(CAS)된다. 같은 내용은 세대가
   몇 개든 한 번만 저장·전송된다.
4. 자산과 세션(티어 A/D)은 바이트 그대로 보존한다. CRLF·파일모드 정규화를
   하지 않으므로 "아무것도 안 바꿨는데 수백 파일 변경"이 원리적으로 없다.
   설정(티어 B)만 기계 중립형으로 변환해 공유한다.

## 3-way 판정표 (정본)

경로마다 세 값을 본다: base(마지막 동기화가 합의한 해시, 로컬 state.json),
local(지금 스캔), remote(HEAD 매니페스트). `–` 는 없음.

| # | base | local | remote | 판정 | 이유 |
|---|---|---|---|---|---|
| 1 | – | – | – | 없음 | |
| 2 | – | A | – | 올림 | 새 로컬 파일 |
| 3 | – | – | A | 내림 | 다른 머신의 새 파일 |
| 4 | – | A | A | 없음 | 양쪽이 같은 내용을 만듦 |
| 5 | – | A | B | 충돌* | base 없는 분기 |
| 6 | A | A | A | 없음 | |
| 7 | A | B | A | 올림 | 로컬만 편집 |
| 8 | A | A | B | 내림 | 원격만 편집 |
| 9 | A | B | B | 없음 | 양쪽이 같은 편집 |
| 10 | A | B | C | 충돌* | 진짜 분기 |
| 11 | A | – | A | 내림 | 로컬 삭제 → 복원 (삭제 무전파) |
| 12 | A | – | B | 내림 | 로컬 삭제 + 원격 편집 → 원격본 |
| 13 | A | A | – | 올림 | 방어적 (엔트리는 불멸이지만) |
| 14 | A | B | – | 올림 | |
| 15 | B | – | – | 없음 | 지웠고 카탈로그에도 없음 |

\* `.jsonl`(티어 D)은 충돌 전에 자동 해소를 시도한다: 한쪽이 다른 쪽의
바이트 접두어면 긴 쪽 채택(append-only), 라인 독립 파일(history)은 공통
접두어 + 양쪽 신규 라인 합집합. 둘 다 아니면 사용자에게 묻는다.

충돌 선택지: 이 컴퓨터 것 / 클라우드 것 / **둘 다 보존**(원격본이
`파일명.bottari-r<세대>` 로 옆에 남고 카탈로그에도 등재).

미해소 충돌이 있으면 **충돌 없는 경로만으로 세대를 커밋한다.** 합집합에서는
부분 커밋이 항상 안전하다.

## 세대 커밋 프로토콜

Drive에는 compare-and-swap이 없다. 그래서:

1. 매니페스트는 **고유 이름·생성 전용**으로 올린다 (Drive는 동명 파일을
   허용하므로 이름은 신뢰하지 않는다).
2. 올린 뒤 meta의 HEAD를 다시 읽는다. 그대로면 meta 를
   `{head, headManifestId}` 로 갱신해 커밋 완료. 바뀌었으면 **내가 올린
   매니페스트를 지우고** 새 HEAD 위에서 재병합한다 — 이미 올린 객체는 CAS
   라 전부 재사용되므로 재시도 비용은 매니페스트 하나다.
3. 체인은 매니페스트 안의 parentManifestId(파일 id)로 걷는다. 파일 이름은
   표시용일 뿐이다.
4. lock.json(TTL 10분)은 경합을 줄일 뿐 정합성의 근거가 아니다. 정합성은
   2번이 지킨다.

`restore --generation N` 은 체인을 걸어 그 세대의 파일을 물질화한다.
지우는 것은 없고, 다음 sync 가 복원된 상태를 **새 세대로** 올린다.
`prune --keep N` 은 체인 밖 매니페스트와 미참조 객체만 지운다.

## Drive 레이아웃

```
bottari/
├── bottari.meta.json    # 유일한 평문: KDF 파라미터, 래핑된 DEK, HEAD
├── lock.json            # 동기화 중 임시
├── generations/         # 봉인된 매니페스트 (고유 이름)
├── objects/             # 봉인된 콘텐츠. 이름 = HMAC(파생키, 평문해시)
└── machines/            # 머신별 도구 목록 (병합 대상 아님)
```

## 실기기 릴리스 체크리스트

1. A머신 `init`(흐름 A) → Drive 웹에서 폴더 확인, 평문은 meta 하나
2. B머신 `init`(흐름 B) → 자산 바이트 diff 0건, 복원된 설정에 A머신 잔재 0건
3. 교차 편집 sync 2회 → 수렴, 3회째는 무변경(멱등)
4. 같은 파일 양쪽 편집 → 충돌 질의 → 둘 다 보존 → 두 사본 확인
5. 한쪽 삭제 → sync → 되살아남
6. 대형 세션 append → 전송량 = 청크 1개
7. macOS에서 한글 경로 수신 → NFC/NFD 무결
8. `restore --generation 1` → 최초 상태 복원
9. 키체인 항목 삭제 후 기동 → 재로그인 유도
